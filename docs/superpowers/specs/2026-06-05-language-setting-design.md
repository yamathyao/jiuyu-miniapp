# 方庭九屿语言设置与双语文案设计

## 背景

方庭九屿当前已经具备首页、难度选择、继续游戏、新开一局、棋盘场景、提示与检查能力，并已开始按难度切换 UI 气质。

当前产品仍存在一个明显缺口：所有用户可见文本都写死在各个模块中，且默认只有简体中文，无法统一切换语言。随着首页、棋盘、提示检查、设置入口逐步成型，如果现在不把语言能力收成统一结构，后续新增文本会继续分散，最终形成“部分可翻译、部分写死”的状态。

## 变更说明

2026-06-05 后续迭代已将“首页内嵌设置展开”替换为：

- 独立设置页
- 独立语言页
- 棋盘页设置入口

与设置入口结构相关的后续维护，以
`docs/superpowers/specs/2026-06-05-jiuyu-settings-ui-redesign-design.md`
为准。

本轮目标是在不引入重框架的前提下，为方庭九屿建立一套完整且可扩展的双语机制，首批支持：

- `zh-CN`
- `en`

并覆盖 **全部用户可见文本**，而不仅仅是首页按钮或局部提示。

## 目标

- 支持简体中文与英文两种语言
- 语言属于全局设置，可持久化保存
- 启动时按已保存语言渲染首页
- 切换语言后立即重绘当前场景
- 所有用户可见文本都统一从 i18n 层读取
- 难度名称也纳入翻译
- 提示与检查反馈文案也纳入翻译
- 保持现有难度逻辑、存档结构和棋盘主循环不被破坏

## 非目标

- 不引入第三方 i18n 框架
- 不在本轮实现更多语言
- 不新增独立完整设置页
- 不改变内部难度枚举值
- 不翻译品牌名“方庭九屿”

## 语言范围

### 本轮支持语言

- `zh-CN`
- `en`

### 默认语言

- 默认值为 `zh-CN`

### 回退策略

- 若读取到未知 locale，则统一回退到 `zh-CN`
- 若旧 settings 中不存在 language 字段，则自动补默认 `zh-CN`

## 覆盖范围

本轮要求覆盖 **全部用户可见文本**，包括但不限于：

### 首页

- 副标题
- 主按钮
- 次按钮
- 难度名称
- 当前难度文案
- 设置文案
- 底部状态文案
- 设置区中的语言项文案

### 棋盘页

- 顶部标题区文本
- 难度标签
- 反馈区消息

### 工具栏

- `笔记 / 撤销 / 擦除 / 提示 / 检查`

### 服务层返回文案

- `hint-engine` 返回的提示消息
- `checker` 返回的检查消息

### 后续要求

- 本轮完成后，任何新增用户可见文本都不得直接写字面量，必须先进入 i18n 字典

## 品牌与难度翻译规则

### 品牌名

- `方庭九屿` 保持不翻译
- 无论当前语言是 `zh-CN` 还是 `en`，品牌显示都保持 `方庭九屿`

### 难度内部值

内部逻辑与数据仍使用：

- `beginner`
- `intermediate`
- `skilled`
- `expert`

### 难度显示文本

所有面向用户显示的难度名称都通过 i18n 输出：

- `beginner` -> `新手` / `Beginner`
- `intermediate` -> `进阶` / `Intermediate`
- `skilled` -> `熟练` / `Skilled`
- `expert` -> `专家` / `Expert`

覆盖位置包括：

- 首页难度卡片
- 首页“当前难度”
- 棋盘页顶部难度标签
- 未来提示/检查中若出现难度描述，也沿用同一翻译

## 交互设计

### 设置入口

- 继续使用首页现有 `设置` 入口
- 本轮不跳转独立设置页
- 点击 `设置` 后，在首页下半区展开一个轻量设置面板

### 设置面板首批内容

本轮先只放一个设置项：

- `语言 / Language`
- `简体中文`
- `English`

### 交互规则

- 当前语言高亮显示
- 点击 `简体中文`：切换到 `zh-CN`
- 点击 `English`：切换到 `en`
- 切换后立即：
  - 更新内存状态
  - 持久化到 `settings.language`
  - 重绘当前场景

### 场景更新规则

- 如果当前在首页，切换后首页立即变更为目标语言
- 如果后续支持从棋盘页返回首页，首页依然应按当前语言显示
- 当前阶段棋盘页不强制新增第二个语言入口，首页设置区是主入口

## 全局设置模型

`settings` 从当前的单字段扩展为：

```js
{
  preferredDifficulty: "beginner",
  language: "zh-CN"
}
```

### 状态原则

- `language` 属于全局设置
- 不跟单局游戏存档绑定
- 不跟难度绑定
- 修改语言不会改变当前对局数据

### 启动流程

启动时统一执行：

1. 读取 `settings`
2. 读取 `preferredDifficulty`
3. 读取 `language`
4. 创建翻译器
5. 进入首页并按当前语言渲染

## 技术方案

本轮采用轻量集中式 i18n：

- 单一字典源
- 单一翻译入口
- 场景层与服务层统一依赖 `t(key, params)`

不使用：

- 第三方 i18n 框架
- 多级复杂运行时注册
- 重型命名空间拆分

## 代码结构

### 新增目录

- `js/i18n/locales.js`
- `js/i18n/index.js`

### `js/i18n/locales.js`

放置 `zh-CN` 与 `en` 两份字典。

字典结构按领域分组，但首版保持在单文件中，降低复杂度。建议包含：

- `common`
- `home`
- `board`
- `toolbar`
- `difficulty`
- `hint`
- `check`
- `settings`

### `js/i18n/index.js`

提供轻量能力：

- `DEFAULT_LOCALE`
- `isSupportedLocale(locale)`
- `normalizeLocale(locale)`
- `createTranslator(locale)`

其中 `createTranslator(locale)` 返回：

```js
t(key, params)
```

用于读取文案与做简单插值。

## 模块接入边界

### `storage.js`

需要扩展：

- `loadSettings`
- `saveSettings`

要求：

- 支持读写 `language`
- 对旧数据缺失 `language` 的情况自动补默认值

### `main.js`

负责：

- 持有 `language`
- 根据 `settings.language` 创建翻译器
- 把 `t` 或已翻译文本传给场景/UI/服务层
- 在语言切换时立即持久化并重绘

建议新增状态：

```js
let language = "zh-CN";
```

并在设置变化后更新翻译器实例。

### `home-scene.js`

职责保持为绘制与命中，不再生产写死文案。

需要改造的内容：

- 标题副文案
- 按钮文案
- 难度文案
- 当前难度文案
- 设置文案
- 底部状态文案
- 设置区里的语言文案

它应通过外部传入的 `t` 或已翻译文案进行绘制。

### `board-scene.js`

继续只负责绘制，不负责生成文本。

需要接收：

- 标题
- 难度标签
- 反馈文案

### `toolbar.js`

工具按钮 label 改为使用翻译结果，例如：

- `toolbar.note`
- `toolbar.undo`
- `toolbar.erase`
- `toolbar.hint`
- `toolbar.check`

### `hint-engine.js`

不再写死中文消息。

应改为：

- 根据 `difficulty + level` 选择文案 key
- 用 `t(...)` 返回当前语言消息

### `checker.js`

不再直接返回中文消息。

应改为通过 `t(...)` 输出：

- 发现问题时的提示
- 未发现问题时的提示

## 文案规范

### 首页与设置

- `zh-CN` 保持当前偏自然、温和的语气
- `en` 使用简洁、自然、不过度营销的表达

### 棋盘与专业难度

- `skilled / expert` 对应英文文案保持更短、更干练
- 不使用夸张语气或过度游戏化表达

### 提示与检查

- 初学难度的提示语保持陪伴感
- 高难度的提示语更偏解题辅助
- 两种语言都保留这种分级风格差异

## 测试策略

本轮按 TDD 执行，至少补三类测试。

### 1. i18n 基础测试

- `createTranslator("zh-CN")` 返回中文文案
- `createTranslator("en")` 返回英文文案
- 不支持的 locale 自动回退 `zh-CN`
- 插值文案可正常工作

### 2. 设置存储测试

- `loadSettings` 默认返回：

```js
{
  preferredDifficulty: "beginner",
  language: "zh-CN"
}
```

- `saveSettings` 能写入 `language: "en"`

### 3. 行为回归测试

- 首页文案能按语言切换
- 首页难度名称能按语言切换
- 工具栏标签能按语言切换
- `hint-engine` 返回消息能按语言切换
- `checker` 返回消息能按语言切换
- `main` 启动时能使用 settings 里的语言渲染首页

## 实现顺序

建议按以下顺序实施：

1. 先补 i18n 与 settings 的失败测试
2. 实现 `js/i18n/` 基础能力
3. 扩展 `storage.js` 的 language 持久化
4. 接入首页与设置区语言切换
5. 接入棋盘页与工具栏翻译
6. 接入 `hint-engine` 与 `checker`
7. 做启动、切换与回归验证

## 风险与约束

- 当前文案分散在多个模块中，若只改 UI 层，会遗漏服务层消息
- 若将翻译逻辑写回场景内部，会再次分散 i18n 入口
- 若直接把内部枚举值改成中文，会破坏现有 difficulty 逻辑与测试
- 若不在本轮立下“新增文本必须走字典”的规则，后续很快会回到混杂状态

## 验收标准

- 首页可切换简体中文与英文
- 切换后立即重绘，无需重启
- 用户可见文本全部随语言变化
- 难度名称也随语言变化
- 提示与检查消息也随语言变化
- 品牌名 `方庭九屿` 保持不翻译
- `node --test tests/game-engine.test.js` 继续通过

## 结论

本轮语言设置不是给首页补两个按钮，而是为方庭九屿建立一套完整、统一、可持续扩展的双语基础能力：

- 语言成为全局设置
- 首页设置区承接语言切换
- 难度名称纳入翻译
- 提示与检查消息纳入翻译
- 所有用户可见文本统一从 i18n 层输出

这样首版虽然只支持 `zh-CN / en`，但后续继续加语言或新增页面时，都不需要回头重构整条文案链路。
