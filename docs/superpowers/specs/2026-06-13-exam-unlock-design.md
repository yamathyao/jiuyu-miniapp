# 难度考试与积分解锁设计

## 背景

当前项目已经具备：

- 首页难度选择
- 不同难度的新开局
- 本地统计与通关结算

但还没有以下能力：

- 难度解锁状态
- 首次定级考试
- 考试失败后的保留继续流程
- 通过积分解锁更高难度

本设计用于在不推翻现有主流程的前提下，为小游戏补上一层稳定的进度系统。

## 目标

新增一套“考试优先、积分保底”的难度解锁机制：

1. 新玩家第一次接触更高难度时，可以通过考试直接解锁该难度及以下难度。
2. 考试在限时内未通关时，本局不退出，给出一次失败提示后允许继续完成。
3. 玩家想挑战更高难度时，可以再次选择考试。
4. 考试没有通过时，也可以通过在当前已解锁难度正常通关累计积分来解锁下一难度。

## 非目标

- 不改动数独题库与题目难度定义方式。
- 不引入远端账号、云端存档或跨设备同步。
- 不新增复杂货币系统、商城或消耗型道具。
- 不在本次设计中重做首页整体视觉，只做围绕考试与锁定态的增量改造。

## 当前代码约束

现有实现中：

- `js/main.js` 负责首页、开局、棋盘、通关结算与本地状态串联。
- `js/services/storage.js` 目前只持久化 `currentGame`、`settings`、`stats`。
- `js/services/stats-service.js` 负责通关摘要和统计累积，但不负责解锁。
- `js/scene/home-scene.js` 已有难度选择 UI，但所有难度默认都可选。

因此本次改造应新增独立的进度模型，而不是把“解锁状态”硬塞进 `settings` 或 `stats`。

## 方案选择

最终采用：独立考试模式 + 独立进度存档 + 通关积分补充解锁。

选择理由：

- 普通局与考试局职责分明，后续扩展规则不容易互相污染。
- 可以最大化复用现有棋盘玩法，而不是重写一套考试页面。
- 积分和统计分层明确，后续调数值时改动边界清晰。

## 核心规则

### 1. 解锁基础规则

- 默认初始仅解锁 `beginner`。
- 玩家可正常选择所有已解锁难度。
- 未解锁难度显示为锁定态，不可直接作为普通局开局。

### 2. 考试通过规则

- 考试通过标准为：在该难度规定时间内完整通关当前考试棋局。
- 通过某一难度考试后，立即解锁该难度及以下所有难度。
- 已通过的考试结果永久保留到本地进度。

### 3. 考试失败规则

- 考试开始后，系统记录倒计时截止时间。
- 到达时限仍未通关时：
  - 立即弹出一次提示，明确本次考试未通过。
  - 当前棋局继续保留，玩家可继续完成。
  - 本次考试状态记为失败，不会因为超时后补完而改判为考试通过。
- 在同一局考试超时后继续完成时：
  - 仍计为一次正常通关。
  - 仍可获得通关积分。
  - 但不触发考试解锁。

### 4. 积分解锁规则

- 玩家在“当前已解锁难度”完成普通对局，获得积分。
- 积分为永久累计值，不消耗回退。
- 当累计积分达到某个难度门槛时，直接解锁该难度。
- 积分解锁与考试解锁并行存在，任一路径达成即可解锁。

## 进度模型

新增独立 `progress` 存档，职责只覆盖考试、解锁、积分。

建议结构：

```js
{
  unlockedDifficulties: ["beginner"],
  totalPoints: 0,
  examRecordByDifficulty: {
    beginner: {
      passed: false,
      attempted: false,
      failedCount: 0,
      bestRemainingSeconds: 0
    },
    intermediate: {
      passed: false,
      attempted: false,
      failedCount: 0,
      bestRemainingSeconds: 0
    },
    skilled: {
      passed: false,
      attempted: false,
      failedCount: 0,
      bestRemainingSeconds: 0
    },
    expert: {
      passed: false,
      attempted: false,
      failedCount: 0,
      bestRemainingSeconds: 0
    }
  }
}
```

说明：

- `unlockedDifficulties` 是权威解锁来源。
- `totalPoints` 是累计积分总额。
- `examRecordByDifficulty` 记录玩家是否考过、是否通过，以及失败次数。
- `bestRemainingSeconds` 用于后续若要展示“最佳考试表现”时保留扩展位，本次实现可以只维护简单数值。

## 考试模式

考试局继续复用现有棋盘页，但运行时增加 `exam session` 概念。

建议运行态结构：

```js
{
  mode: "exam",
  difficulty: "intermediate",
  timeLimitSeconds: 600,
  deadlineReached: false,
  result: "pending"
}
```

其中：

- `mode` 区分普通局与考试局。
- `deadlineReached` 控制“超时失败提示只触发一次”。
- `result` 取值为 `pending | passed | failed`。

## 推荐时限与积分数值

本次优先采用简单、易调的首版数值。

### 考试时限

- `beginner`：不需要考试
- `intermediate`：10 分钟
- `skilled`：15 分钟
- `expert`：20 分钟

理由：

- 首版实现以体验验证为主，时限略宽松，避免新机制刚上线就过于挫败。
- 更高难度给更长时间，符合谜题复杂度递增。

### 通关积分

- 通关 `beginner`：+10
- 通关 `intermediate`：+20
- 通关 `skilled`：+30
- 通关 `expert`：+40

### 积分解锁门槛

- 解锁 `intermediate`：100
- 解锁 `skilled`：250
- 解锁 `expert`：450

数值关系：

- 只玩 `beginner`，约 10 局可解锁 `intermediate`
- 只玩 `intermediate`，在已解锁后约 8 局可补开 `skilled`
- 考试仍是更快路径，积分更像稳定保底路径

## 用户流程

### 流程 1：首次普通进入

1. 玩家进入首页。
2. `beginner` 为已解锁状态。
3. 其他难度显示锁定态。
4. 玩家可以直接开始 `beginner` 普通局。

### 流程 2：点击未解锁难度

1. 玩家点击一个未解锁难度。
2. 系统弹出解锁操作面板。
3. 面板提供两个主要动作：
   - `参加该难度考试`
   - `查看当前积分解锁进度`
4. 若存在更低一级的未通过考试，也可在文案中提示“可改考下一难度”。

### 流程 3：考试通过

1. 玩家从首页对未解锁难度发起考试。
2. 系统创建考试局并开始计时。
3. 若在时限内通关：
   - 标记该难度考试通过
   - 解锁该难度及以下难度
   - 弹出“考试通过”结果文案
   - 同时结算本局普通通关积分

### 流程 4：考试超时

1. 考试倒计时归零时，玩家尚未通关。
2. 系统立即弹出一次提示：
   - 本次考试未通过
   - 当前可继续完成本局
   - 或返回后改考下一难度
3. 玩家留在当前棋盘继续游玩。
4. 若最终完成：
   - 仅作为普通通关处理
   - 发放积分
   - 不触发考试解锁

### 流程 5：积分解锁

1. 玩家持续游玩当前已解锁难度。
2. 每次通关后累积积分。
3. 达到指定门槛时，自动解锁下一难度。
4. 首页对应难度从锁定态变为可选态。

## 首页与交互设计

### 首页难度卡片

- 已解锁难度：保持现有可点击选择样式。
- 未解锁难度：新增锁定态视觉。
- 锁定态需要展示：
  - 锁定标识
  - 考试入口提示
  - 当前积分或剩余积分简要信息

### 解锁操作弹层

首版建议采用轻量弹层，不新增独立页面。

弹层展示：

- 当前目标难度名称
- 考试时限
- 当前累计积分
- 解锁该难度所需积分
- 主按钮：`参加考试`
- 次按钮：`继续赚积分`
- 若适用，补充文案：`也可改挑战次一难度考试`

### 首页底部辅助文案

可在难度区或页脚补一行短文案，解释：

- 考试可快速解锁
- 普通通关可累计积分慢慢解锁

## 棋盘与考试态展示

考试局进入棋盘后，建议新增以下可见反馈：

- 顶部显示 `考试中`
- 计时区额外展示 `剩余时间`
- 超时后展示醒目但不过度打断的失败提示

首版不需要做复杂暂停逻辑，只需确保：

- 倒计时跟随已有计时器逻辑更新
- 超时提示只出现一次
- 超时后仍能继续正常下棋、检查、提示与通关

## 通关结算规则

### 普通局通关

- 沿用现有通关结算
- 新增积分获得展示
- 若积分首次达到解锁门槛，追加“新难度已解锁”提示

### 考试局通关

- 若限时内完成：
  - 结算为考试通过
  - 同时给出积分奖励
- 若超时后完成：
  - 结算为普通通关
  - 给出积分奖励
  - 明确提示“本次考试未通过，但已获得积分”

## 存档与兼容

需要在 `storage` 中新增 `progress` 键。

兼容策略：

- 老玩家首次升级到新版本时：
  - 若本地没有 `progress`，自动创建默认进度
  - 默认仍只解锁 `beginner`
- `settings`、`stats`、`currentGame` 保持兼容，不迁移已有结构

这样可以把新功能与旧存档风险隔离开。

- 新增 `progress` 读写
- 增加 `loadProgress` / `saveProgress`
- 增加默认 `progress` 创建与校验

## 边界情况

### 1. 考试超时瞬间同时通关

判定优先级以“是否在超时前完成”为准。

- 若先完成再到时：算考试通过
- 若先到时再完成：算考试失败后的普通通关

实现上应避免同一秒内重复触发两套结果。

### 2. 玩家退出考试局再回来

首版建议：

- 考试局作为普通当前对局一起存档
- 但关闭重进后，不继续保留“考试计时有效性”
- 为避免离线暂停作弊，重新进入后该局只按普通局继续，不再保留考试资格

这条规则要在实现中写死并在文案中尽量说清。

### 3. 已经通过更高难度考试

若玩家已经通过 `skilled` 考试，则：

- `beginner`、`intermediate`、`skilled` 都视为已解锁
- 不需要再单独补考更低难度

### 4. 积分超过多个门槛

若累计积分一次性超过多个门槛，则按门槛顺序自动解锁所有已满足条件的难度。

## 测试策略

首版采用 Level 1 到 Level 2 之间的验证强度：

- 对核心进度规则使用单测
- 对首页和棋盘交互以定向验证为主

重点覆盖：

1. 默认进度初始化
2. 考试通过解锁当前及以下难度
3. 考试超时后补完只给积分不解锁
4. 普通通关累计积分并自动解锁
5. 老存档升级时不破坏现有设置与统计

## 风险与权衡

### 1. `main.js` 继续变大

解决方式是把进度规则和考试规则尽量收进 `progress-service`，只把流程编排留在 `main.js`。

### 2. 首页弹层交互是新增复杂点

首版用轻量弹层即可，不新增新页面，不引入复杂手势关闭逻辑。

### 3. “考试失败但继续游玩”容易让用户误解

需要在超时提示和通关结算中都明确说明：

- 本次考试未通过
- 但你仍获得了正常通关积分

## 最终设计结论

本次实现新增一层独立进度系统，以 `progress` 管理解锁、考试与积分；首页负责展示锁定态与考试入口；棋盘继续复用现有玩法，只增加考试运行态与超时判定。这样可以在不推翻当前架构的前提下，落地“考试快速解锁 + 积分保底解锁”的完整闭环。
