# 方庭九屿首页入口与分级 UI / 提示检查设计

## 背景

方庭九屿当前已经完成微信小游戏单场景数独主循环，包含棋盘渲染、选格、填数、笔记、擦除、撤销，以及本地存档与继续游戏。

在继续扩展提示与检查之前，当前产品结构暴露出两个更基础的问题：

- 启动即进入棋盘，缺少首页入口与难度选择入口
- 棋盘和下方按钮整体偏靠上，界面呼吸感不足，视觉层级不够清楚

本轮设计不再只是“补提示和检查”，而是把启动入口、难度选择、棋盘布局、按钮气质和提示检查分级能力统一整理成一条新的主线。

产品名从本轮开始统一使用 **方庭九屿**。

## 变更说明

本设计文档中提到的“首页轻量展开设置区”已在后续迭代中收敛为：

- 独立设置页
- 独立语言页
- 棋盘页顶部设置入口

页面结构与交互流以后续文档
`docs/superpowers/specs/2026-06-05-jiuyu-settings-ui-redesign-design.md`
为准。

## 目标

- 小游戏启动后先进入首页/设置页，而不是直接进入棋盘
- 首页承接 `继续游戏`、`新开一局`、`难度选择` 和 `设置` 入口
- 棋盘页整体下移，避免主内容贴顶部
- 数字区和工具区按钮增加轻立体感
- `beginner / intermediate` 与 `skilled / expert` 呈现不同 UI 气质
- 难度直接绑定提示/检查强度
- 不破坏现有存档、继续游戏和棋盘核心操作闭环

## 本次范围

### 包含

- 新增首页/设置页场景
- 启动默认进入首页/设置页
- 首页显示产品名 **方庭九屿**
- 首页提供 `继续游戏`、`新开一局`、`难度选择`、`设置`
- 首页支持 4 档难度选择：`beginner / intermediate / skilled / expert`
- 棋盘页整体下移并重排上方留白
- 数字区和工具区按钮改为轻立体风格
- 按难度切换主题气质
- 按难度切换提示/检查强度
- 保持本地存档、继续游戏、笔记、撤销、擦除可继续工作

### 不包含

- 完整独立设置页
- 统计页与完成页重做
- 复杂动效系统
- 多页面路由框架
- 一键填入答案
- 实时自动排错
- 高阶数独技巧

## 信息架构

本轮采用“双场景 + 总入口”结构：

- `main.js`
- `home-scene.js`
- `board-scene.js`
- `toolbar.js`

职责如下：

### `main.js`

只负责：

- 启动
- 读取存档与设置
- 场景切换
- 持有共享状态
- 将状态分发给首页和棋盘场景

### `home-scene.js`

负责：

- 绘制首页/设置页
- 展示产品名 **方庭九屿**
- 展示 `继续游戏` / `新开一局`
- 展示难度选择
- 展示 `设置` 入口
- 返回首页点击命中结果

### `board-scene.js`

继续负责：

- 棋盘绘制
- 反馈区绘制
- 提示目标格与错误格标记
- 根据主题切换棋盘视觉样式

### `toolbar.js`

继续负责：

- 数字区绘制与命中
- 工具区绘制与命中
- 根据主题切换按钮样式

## 启动流与场景切换

### 启动流

启动后统一执行：

1. 读取 `currentGame`
2. 读取 `settings`
3. 进入 `home` 场景

### 首页行为

首页根据是否存在有效存档显示不同主按钮层级：

- 有存档：`继续游戏` 为最突出的主按钮
- 无存档：`新开一局` 为最突出的主按钮

### 进入棋盘

- 点击 `继续游戏`：恢复当前对局并进入 `board`
- 点击 `新开一局`：按当前选中难度创建新局并进入 `board`

### 棋盘页返回与设置

棋盘页右上角保留一个小型 `设置` 入口，为后续扩展完整设置页或返回首页预留入口。

当前阶段不强制实现复杂返回流，但要在结构上预留入口位置。

## 首页/设置页设计

首页/设置页采用轻量入口页，不做复杂大厅。

从上到下结构建议为：

1. 顶部品牌区
2. 主操作区
3. 难度选择区
4. 次级入口区
5. 底部轻信息区

### 顶部品牌区

显示：

- `方庭九屿`
- 一句轻量副标题

副标题风格随难度主题切换，但不影响品牌名稳定。

### 主操作区

包含：

- `继续游戏`
- `新开一局`

规则：

- 有存档时，`继续游戏` 为主按钮
- `新开一局` 仍需清楚可见，但降为次按钮

### 难度选择区

直接展示四档：

- `beginner`
- `intermediate`
- `skilled`
- `expert`

当前选中难度决定：

- 新开一局的题目难度
- 首页主题气质
- 棋盘主题气质
- 提示/检查强度

### 次级入口区

先提供一个 `设置` 入口。

当前阶段 `设置` 实现为轻量展开区，用于承接后续更多设置能力，但本轮不扩展为完整独立设置页。

### 底部轻信息区

可显示：

- 当前是否有可继续对局
- 当前选中难度
- 上次对局难度

信息保持轻量，不做复杂统计卡片。

## 棋盘页布局整理

当前棋盘页的核心问题不是功能缺失，而是布局重心过高。

本轮调整原则：

- 棋盘整体下移
- 上方留出呼吸区
- 状态区与棋盘、棋盘与按钮之间的垂直节奏更稳定

### 建议布局

从上到下：

1. 顶部轻状态区
2. 棋盘
3. 数字区
4. 工具区

### 顶部轻状态区

显示：

- `方庭九屿`
- 当前难度
- 反馈文案
- 小型 `设置` 入口

该区域不做复杂信息堆叠，重点是让棋盘下移并保持界面重心稳定。

## 难度与主题分级

### 四档难度

- `beginner`
- `intermediate`
- `skilled`
- `expert`

### 主题分组

采用两组气质：

- `beginner / intermediate`
- `skilled / expert`

### `beginner / intermediate`

整体方向：

- 更可爱
- 更轻松
- 更有陪伴感

视觉特征：

- 颜色更柔和
- 可使用温暖或更明亮的辅助色
- 按钮圆角更柔软
- 反馈文案语气更亲和
- 错误提示避免攻击性红色

### `skilled / expert`

整体方向：

- 更专业
- 更简洁
- 更干练

视觉特征：

- 颜色更克制
- 留白和分隔更清楚
- 文案更短更专业
- 反馈更像解题辅助而不是陪练提示

### 主题变化边界

允许变化：

- 页面背景
- 棋盘高亮色
- 反馈区样式
- 工具栏按钮颜色与层次
- 难度卡片样式
- 文案语气

保持不变：

- 页面结构
- 棋盘规则
- 交互路径
- 按钮位置逻辑

## 按钮立体感

本轮按钮采用“轻立体”，而不是厚重游戏按钮。

### 共性原则

- 所有主要按钮都有轻微高光和阴影
- 按下态有轻微“陷下去”的感觉
- 立体感服务于层级，不喧宾夺主

### `beginner / intermediate`

- 圆角更柔和
- 高光更轻软
- 色彩更温暖
- 视觉更像亲和的陪练工具

### `skilled / expert`

- 立体感更克制
- 边缘更干净
- 色彩更收敛
- 视觉更像专业解题工具

## 难度与提示/检查绑定

提示与检查继续直接绑定 `puzzle.difficulty`。

### 检查模式

- `beginner` -> `solution`
- `intermediate` -> `solution`
- `skilled` -> `conflict`
- `expert` -> `conflict`

### 提示上限

- `beginner` -> `direction -> cell -> technique -> answer`
- `intermediate` -> `direction -> cell -> technique`
- `skilled` -> `direction -> technique`
- `expert` -> `technique`

### 技巧范围

首版仅做：

- `naked-single`
- `hidden-single`
- `basic-elimination`

## 共享状态与持久化

`main.js` 统一持有：

```js
let activeScreen = "home";
let selectedDifficulty = "beginner";
let currentGame = null;
let selectedIndex = -1;
let noteMode = false;
let feedbackMessage = "";
let feedbackType = "info";
let issueIndexes = [];
let hintState = {
  currentLevel: null,
  targetIndex: -1
};
let settings = {
  preferredDifficulty: "beginner"
};
```

### 持久化数据

继续保存：

- `currentGame`

新增保存：

- `settings.preferredDifficulty`

### 规则

- 点击首页难度卡片后，更新 `preferredDifficulty`
- 点击 `新开一局` 时，按 `selectedDifficulty` 创建新局
- 点击 `继续游戏` 时，恢复当前存档并进入棋盘

## 本轮实现顺序

建议按以下顺序实施：

1. 先把启动结构改成 `home + board`
2. 接入 `preferredDifficulty` 和首页难度选择
3. 接入 `继续游戏 / 新开一局`
4. 重排棋盘页布局，让棋盘和按钮整体下移
5. 实现分级主题和轻立体按钮
6. 把提示/检查分级能力接回新入口结构
7. 回归验证继续游戏、存档、棋盘核心操作

## 验收标准

- 启动后先看到首页/设置页
- 首页显示产品名 **方庭九屿**
- 有存档时，`继续游戏` 是最突出的主按钮
- 首页能直接选择难度并启动新局
- 棋盘页主内容明显比现在更靠下、更舒展
- 按钮具备轻立体感且可读性稳定
- `beginner / intermediate` 与 `skilled / expert` 的页面气质有明确差异
- 难度切换后，提示/检查强度和主题都会变化
- 继续游戏、新开一局、提示、检查、笔记、撤销、擦除、存档不被破坏

4. 切换难度后首页视觉气质变化明显
5. 点击 `新开一局` 后进入对应难度主题的棋盘
6. 棋盘与按钮整体更靠下，不再贴顶部
7. 按钮有轻立体感，点击态清楚
8. 提示和检查仍按难度分级
9. 继续游戏与存档恢复不受破坏

## 风险与边界

- 当前代码仍以单场景思路构建，本轮需要先把入口结构拆清，否则首页和棋盘逻辑会挤在一起
- 若首页一次塞入过多功能，会把入口页做重，因此当前阶段必须坚持极简首页
- 若主题变化过大，会影响熟悉感，因此只能切换气质，不能切换结构
- 若按钮立体感过重，会削弱专业感，因此必须保持“轻立体”而不是玩具按钮

## 结论

本轮的核心不是单独美化棋盘，而是把 **方庭九屿** 的启动入口、难度选择、棋盘布局、按钮气质和提示/检查分级能力整理成一套更完整的体验结构：

- 先进入首页
- 首页决定从哪里开始、以什么难度开始
- 棋盘页回到更舒展、更稳定的视觉重心
- 难度同时影响帮助强度与 UI 气质
