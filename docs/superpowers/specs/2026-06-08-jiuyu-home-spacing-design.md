# 方庭九屿首页主体留白与纵向节奏设计

## 背景

方庭九屿当前已经完成：

- 首页默认启动
- `继续游戏 / 开始新局 / 难度选择 / 设置` 四类主入口
- 独立设置页与独立语言页
- 首页、设置页、语言页与棋盘页头部的基础风格统一

当前首页的主要问题已经不再是功能缺失，而是主体内容的纵向节奏还不够稳定：

- 品牌区到主操作区之间的关系偏松
- 主按钮、难度区、设置入口和底部状态文案之间更像“功能块堆叠”，不像一个被完整收口的入口页
- `设置` 与底部状态文案的视觉主次还不够明确

因此本轮不新增能力，只处理首页主体留白与纵向节奏，让首页入口更完整、更稳定。

## 目标

- 在不改变首页信息结构的前提下，收口纵向节奏
- 保留品牌区的开场感，但避免与主操作区脱节
- 让主按钮组成为最明确的第一视觉焦点
- 让难度区与设置入口形成稳定的中段视觉轴线
- 进一步弱化底部状态文案，避免与主入口竞争注意力

## 非目标

- 不新增首页功能
- 不调整首页文案内容
- 不改动难度选择逻辑
- 不改动 `设置` 的交互去向
- 不在本轮内处理棋盘页工具栏视觉统一
- 不扩展到设置页、语言页或完成页布局重构

## 设计结论

本轮采用“`B 均衡收口`”方案作为正式方向。

该方案的核心判断是：

- 首页仍然需要保留品牌区作为开场，不适合压成纯工具页
- 但主按钮、难度区、设置入口和底部状态区必须被收成一条更稳定的纵轴
- 整体既要比当前更紧致，也不能紧到失去“首页入口页”的呼吸感

相较于其他方案：

- `A 静雅留白` 的展示气质更强，但主操作区偏散
- `C 紧凑沉稳` 的效率更高，但首页会更像功能页
- `B 均衡收口` 最适合作为当前阶段的主线基准

## 布局策略

首页仍然保持原有五段结构：

1. 品牌区
2. 主操作区
3. 难度选择区
4. 次级入口区
5. 底部状态区

本轮只调整这些区块之间的垂直关系，不改变它们的职责。

### 1. 品牌区

- 品牌区保留顶部留白与开场感
- 但与主操作区之间的距离应适度缩短
- 目标是让用户一眼先读到“方庭九屿”，再自然落到主按钮，而不是出现两个彼此分离的区块

### 2. 主操作区

- `继续游戏 / 开始新局` 继续作为最强视觉焦点
- 两个按钮保持成同一组，彼此间距略紧于当前版本
- 主按钮组与品牌区、难度区之间的关系要更连贯，成为首页中轴的中心段

### 3. 难度选择区

- 难度标题与难度卡保持成一个紧密小节
- 难度区与主按钮组的距离较当前版本略收紧
- 保持它作为第二视觉焦点，但不与主按钮竞争
- 本轮优先处理区块之间的布局关系，不在这里一次性锁死所有颜色、描边和装饰线条细节

### 4. 次级入口区

- `设置` 继续作为独立入口存在
- 它应与难度区形成连续的中下段节奏，而不是像额外漂浮出来的一块
- 视觉上要低于主按钮和难度区，不再承担“第三主角”的权重

### 5. 底部状态区

- 状态文案继续保留
- 与 `设置` 入口之间的距离适度收紧，但整体存在感继续下调
- 目标是让它像尾注，而不是一个独立信息卡

## 视觉扩展约束

- 本轮以布局收口为主，颜色、描边粗细、装饰线条和局部纹样只做最小必要跟随，不做全面重画
- 首页现有 `playful / pro` 两组视觉分层能力需要继续保留
- 调整布局时，不应把按钮、难度卡、设置入口的绘制写死到单一固定风格
- 布局常量与视觉常量应继续解耦，便于后续按难度继续调整颜色关系、线条表达和细节装饰
- 若某些位置必须为了布局同步轻微调整颜色或线条，也应优先复用已有 `visualSpec` 字段，而不是在绘制逻辑里新增分散的魔法值

## 实现边界

本轮预计只涉及首页场景中的布局常量、部分绘制位置与节奏关系：

- `js/scene/home-scene.js`

若需要补充防回归验证，可在以下测试中补布局相关断言：

- `tests/game-engine.test.js`

不应在本轮顺手修改：

- `js/scene/board-scene.js`
- `js/ui/toolbar.js`
- `js/scene/settings-scene.js`
- `js/scene/language-scene.js`

## 验收标准

完成后应满足：

- 品牌区、主按钮组、难度区、设置入口、底部状态文案形成更稳定的纵向节奏
- 首页视觉重心更集中，不再呈现明显的“区块堆叠感”
- `设置` 与底部状态文案的主次关系更清楚
- 不影响首页现有点击命中逻辑
- 不影响 `继续游戏 / 开始新局 / 难度选择 / 设置` 的现有行为

## 验证方式

### 自动化验证

- 运行 `node --test tests/game-engine.test.js`

### 手工验证

在默认小游戏画布下检查：

- 品牌区到主按钮的距离是否更自然
- 主按钮组是否成为明确焦点
- 难度区与设置入口是否形成连续节奏
- 底部状态文案是否被有效弱化

## 风险与约束

- 首页命中区域与视觉位置绑定较紧，调整布局时要避免误伤点击区域
- 当前仓库存在与本任务无关的未提交改动，实施时需要避免误混提交
- 本轮若顺手扩展到棋盘页工具栏，会打破“单点收口”的边界，增加验证成本
