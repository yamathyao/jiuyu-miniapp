# 方庭九屿设置页重设计

## 背景

方庭九屿当前已经具备独立的 `settings` 场景与 `language` 场景，但现有设置页仍然偏轻：

- 只有一个主要可操作项：`语言`
- `当前难度` 只是摘要信息，不能直接修改
- 页面结构虽然清楚，但还不像一个真正成立的设置面板

随着首页、棋盘页、语言页逐步稳定，设置页需要从“过渡页”升级为真正可用的设置容器。

## 目标

- 保持设置页的轻面板感，不做成臃肿的系统设置页
- 让设置页具备真正的可操作性，而不只是展示摘要
- 在设置页内直接支持难度切换
- 保留语言页作为独立二级页
- 让设置页成为后续新增设置项时可继续扩展的稳定容器

## 非目标

- 不重做语言页结构
- 不在本轮引入更多设置项，例如音效、震动、主题开关等
- 不改动难度对应的提示/检查策略逻辑
- 不改动首页与棋盘页的设置入口流向
- 不引入复杂动效或多级设置导航

## 设计结论

本轮采用 `B 轻面板感 + 可扩展容器` 方案。

该方案的核心判断是：

- 设置页仍应保持克制、安静、易读
- 但页面不能只有“一个入口卡 + 两个摘要卡”，否则缺少成立感
- 最合适的补强点就是把 `难度切换` 直接放入设置页，让它成为一个真实可操作的主设置项

## 页面结构

从上到下采用四段式结构：

1. 顶部栏
2. 页面标题区
3. 主设置区
4. 辅助说明区

### 1. 顶部栏

顶部栏继续保留：

- 返回入口
- 右上角轻装饰点缀

这一层不承担信息密度，只负责给页面建立“独立场景”的开头感。

同时还需满足：

- 顶栏的纵向留白应继续压缩
- `返回` 与右上角装饰应形成一条更明确的横向带，而不是彼此悬空

### 2. 页面标题区

标题区包含：

- 页面标题 `设置`
- 一句轻量说明文案

这一区域应比当前更完整，形成一个真正的页头，而不是只把标题摆在上方。

### 3. 主设置区

主设置区包含两类设置：

#### 语言设置

语言继续保持为独立主卡片：

- 显示当前语言
- 显示“可切换”状态
- 点击后进入 `language` 场景

这样可以保持语言切换的清楚边界，不把多个语言控件直接堆在设置页里。

语言区排版还需满足：

- `语言` 标题应更贴近语言卡，减少悬空感
- “进入语言页后立即生效”这类说明应收进语言卡内部，而不是留在卡片外漂浮
- 语言卡内部的主文案、说明与 `切换` 按钮要形成更完整的一组

#### 难度设置

难度设置直接在当前页展示 4 个可点击选项：

- `beginner`
- `intermediate`
- `skilled`
- `expert`

交互规则：

- 点击任意难度卡后立即更新当前 `preferredDifficulty`
- 立即持久化到现有设置存储
- 当前页立即重绘
- 当前选中项要有清楚的激活态

这一组卡片应被看作“设置页内的第一组真实设置控件”，而不是摘要。

难度区的排版还需满足：

- `当前难度：...` 提示应放在难度卡组上方
- 这条提示不再使用底部独立摘要卡，而是作为难度区内部的轻提示
- 用户阅读顺序应为：`难度标题 -> 当前难度提示 -> 四张难度卡`
- 底部说明区不再重复出现一次 `当前难度`
- 每张难度卡里的副文案应比当前更短、更整齐，避免出现拥挤换行与节奏断裂

### 4. 辅助说明区

底部保留 1 到 2 块轻说明卡片，用于承接：

- 当前设置会影响什么
- 后续这里还能继续扩展哪些设置项

它们的作用是帮助页面收尾，同时为未来扩展留出语义空间。

## 视觉方向

本轮继续沿用当前项目的双风格体系，不推翻已有视觉语言：

- `beginner / intermediate`：更温润、更亲和
- `skilled / expert`：更克制、更冷静

但设置页本身统一遵循以下方向：

- 像一个安静、清楚、可继续扩展的轻面板
- 不像系统设置列表
- 不像复杂仪表盘
- 不做厚重拟物或现代玻璃感

## 布局与层级要求

- 语言卡片保持单独一张主卡，不和难度切换混在同一块里
- 难度切换采用 2 x 2 小卡阵列，比当前摘要卡更有“可操作”感
- 主设置区的视觉重心应落在“语言卡 + 难度卡组”，而不是底部说明文案
- 辅助说明区应弱于主设置区，但仍保持页面完整度
- `语言` 与 `难度` 两个 section 标题需要比当前实现更明确，可适当放大，并优先采用居中对齐
- section 标题应从“辅助标注”提升为真正的分区标题，帮助页面建立更清楚的排版节奏

## 可扩展性约束

- 本轮要把设置页做成后续可继续加项的容器
- 新增设置项时，应优先沿用“单张主卡”或“同类选项成组卡片”的结构
- 不应把后续扩展建立在一长串系统式列表之上
- 语言与难度的布局关系，要能自然承接未来的音效、视觉偏好或辅助能力

## 后续视觉收敛补充

- 语言页虽然仍是独立二级页，但整体纵向节奏应与设置页保持一致
- 两页都采用相近的顶部留白、返回按钮尺度、标题面板位置与 section 标题节奏
- 顶部装饰线与按钮内部装饰线可进一步弱化或去除，优先保证规整与干净
- 设置页主内容区采用固定纵向 spacing，而不是按中英文逐段试探微调
- 推荐基准：`hero -> section title = 32px`，`section title -> main card = 20px`，`main card -> next section title = 32px`
- 难度区推荐基准：`section title -> 当前难度提示 = 20px`，`当前难度提示 -> 卡片组 = 20px`，`难度组 -> helper card = 24px`

## 技术落点

本轮预计主要涉及：

- `js/scene/settings-scene.js`
- `js/main.js`
- `js/services/storage.js`
- `js/i18n/locales.js`
- `tests/game-engine.test.js`

其中职责建议如下：

### `js/scene/settings-scene.js`

- 重做设置页布局
- 新增难度卡绘制
- 新增难度卡命中检测

### `js/main.js`

- 接通设置页内难度切换动作
- 更新并持久化 `preferredDifficulty`
- 触发当前页重绘

### `js/services/storage.js`

- 若现有设置持久化已支持 `preferredDifficulty`，则无需扩展 schema
- 若读取/写入链路存在页面假设，需要补齐兼容处理

### `js/i18n/locales.js`

- 补充设置页新说明文案
- 若设置页内直接展示难度说明语，需要补齐对应文案

### `tests/game-engine.test.js`

- 保留现有设置页返回与语言入口测试
- 新增设置页难度选项命中测试
- 新增设置页内切换难度并持久化的主流程测试

## 验收标准

完成后应满足：

- 设置页视觉上已经像一个完整的设置面板
- 页面内可直接切换难度
- 语言入口仍可正常进入语言页
- 当前难度切换后立即生效并持久化
- 设置页仍能从 `home` 和 `board` 正常进入与返回
- 页面结构能明显看出后续可继续扩展

## 验证方式

### 自动化验证

- 运行 `node --test tests/game-engine.test.js`

### 手工验证

在微信开发者工具中检查：

- 设置页是否比当前更完整
- 难度切换是否能立即更新当前显示
- 语言入口是否仍然清楚
- 轻面板感是否成立，而不是变成拥挤的设置列表
- `当前难度` 是否已经移动到难度区上方
- `语言 / 难度` 标题是否更清楚，且与整体排版节奏一致

## 风险与约束

- 设置页新增难度切换后，首页与设置页都可改难度，需要确保共享状态一致
- 当前设置页测试主要覆盖语言入口，新增难度交互后要补足命中与持久化验证
- 页面变丰富后，要避免说明区过重，稀释主设置区的操作焦点
