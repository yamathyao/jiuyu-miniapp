# 九屿数独小程序设计方案

## 背景

本文件整理自 2026-05-22 关于“九屿”数独微信小程序的产品设计讨论，用于在新项目或新线程中继续推进开发。

当前产品名暂定为 **九屿**。它不是一个直白的“数独工具”名称，而是用“九个岛屿”隐喻数独中的九个 3x3 宫格。这个名字更轻、更有记忆点，也方便后续延展出清爽、克制但有一点趣味的视觉语言。

我对这个产品的核心判断是：首版不应该急着做社交、排行、活动、云同步等外围能力，而应该先把单人本地数独体验做顺。最重要的闭环是：**打开快、棋盘顺、提示有用、每天愿意回来**。

## 问题对比表

| 问题 | 现象/信号 | 核心判断 | 当前结论 | 影响 |
|---|---|---|---|---|
| 产品定位 | 想做日常可玩，但也需要排错、提示、候选数等专业能力 | 不能只做小游戏，也不能做成冷冰冰工具 | 定位为“日常可玩 + 专业可调”的数独小程序 | 首页、棋盘、设置和提示系统都要兼顾轻量体验与专业控制 |
| 命名方向 | 不想使用传统九宫格、数独大全一类直白命名 | 名称要有记忆点，同时能承载数独结构隐喻 | 暂定名为“九屿” | 视觉、文案、完成反馈可以围绕“九个区域/岛屿”延展 |
| 用户分层 | 新手怕卡住，老手怕被过度辅助打扰 | 难度不应只控制题目，也应控制辅助强度和视觉气质 | 设置入门、进阶、熟练、专家四档 | 同一套产品可以服务轻度用户和认真解题用户 |
| 提示与排错 | 直接给答案会削弱解题感，不给帮助又容易流失 | 提示需要分层，排错需要按用户水平调节 | 提示分方向、格子、技巧、答案；排错按档位控制 | 降低卡关流失，同时保留挑战感 |
| 数据方案 | 首版目标是稳定、可玩、吸引人 | 不应把核心体验绑定到网络和账号系统 | 采用本地题库、本地存档、本地统计 | 启动快、离线可玩、开发风险低 |
| 视觉风格 | 新手可以更年轻、更鼓励；老手要清爽、安静 | 视觉风格应跟随难度变化，但基础品牌保持统一 | 入门/进阶轻游戏化，熟练/专家清爽专业 | 提升不同用户群体的舒适度 |
| MVP 边界 | 容易被云同步、排行、分享、活动等想法拉大范围 | 首版要验证核心体验，不要过早堆增长功能 | 只做单人本地数独闭环 | 降低实现复杂度，把质量集中在棋盘与提示体验上 |

## 结论对比表

| 主题 | 结论 | 依据 | 风险/边界 |
|---|---|---|---|
| 产品名 | 暂定 **九屿** | “九”对应数独九宫，“屿”带来清爽、独立区域的意象 | 上线前需要做微信小程序名称查重和商标风险检查 |
| 首版定位 | 日常可玩、专业可调 | 既照顾轻度用户，也给认真解题用户足够控制权 | 不追求大而全，暂不做云同步、排行和社交对战 |
| 技术路线 | 本地题库 + 本地存档 + 本地统计 | 最符合首版“稳定、快速、离线可玩”的目标 | 题库质量会变得关键，需要保证唯一解和合理难度 |
| 难度系统 | 入门、进阶、熟练、专家四档 | 难度应该同时影响题目、辅助、排错和视觉气质 | 高级设置不能太复杂，避免新手被配置项劝退 |
| 提示系统 | 方向、格子、技巧、答案四层 | 分层提示能先帮助思考，再允许直接推进 | 首版技巧范围要克制，先覆盖基础技巧 |
| 排错系统 | 新手主动，老手克制 | 不同用户对错误反馈的容忍度不同 | 错误反馈不要过度刺眼，避免打击新手 |
| 棋盘交互 | 手机端优先，单手顺滑 | 数独核心体验集中在棋盘，任何摩擦都会被放大 | 工具按钮要有优先级，避免挤压棋盘 |
| 视觉策略 | 随难度微调体验气质 | 入门/进阶更鼓励，熟练/专家更专业 | 风格变化不能造成品牌割裂，棋盘规则和布局要统一 |
| MVP 范围 | 单人本地数独闭环 | 先证明“每天愿意打开”的核心价值 | 增长功能和商业化功能后置 |

## 关键结论

1. **九屿的首版目标不是功能多，而是核心手感稳。** 数独应用的留存很大程度取决于棋盘输入、候选数、提示、排错和存档这些基础体验是否顺滑。
2. **难度系统要做成综合体验档位。** 入门、进阶、熟练、专家不只是题目难度不同，也应该影响提示粒度、排错强度、候选数辅助和视觉气质。
3. **提示系统要有教学感，而不是只做答案按钮。** 更好的路径是逐层提示：先给方向，再给格子，再解释技巧，最后才给答案。
4. **首版应坚持本地优先。** 本地题库、本地进度、本地统计可以让小程序启动快、离线可玩，也减少账号和服务端复杂度。
5. **视觉上要克制但不冷淡。** “九屿”可以有轻微的游戏感和完成反馈，但不要做成重度闯关或花哨皮肤产品。

## 产品结构

| 页面 | 主要职责 | 设计要点 |
|---|---|---|
| 首页 | 承接继续游戏、今日一题、新开一局、统计和设置入口 | 不放长教程，突出“继续当前局”或“开始今日一题” |
| 棋盘页 | 完成数独核心解题流程 | 棋盘清晰、输入顺滑、工具栏稳定、状态反馈克制 |
| 设置页 | 管理难度、辅助、排错、视觉和计时偏好 | 默认四档即可使用，高级设置作为可选覆盖 |
| 完成页 | 展示完成反馈、用时、错误、提示使用和下一步动作 | 入门档更鼓励，专家档更数据化 |
| 统计页 | 展示完成数、连续天数、最好成绩、平均用时 | 首版保持轻量，不做复杂图表 |

## 首页设计

首页保持轻量，突出当天可玩的内容。

| 模块 | 内容 | 说明 |
|---|---|---|
| 顶部 | 九屿、连续练习天数、设置入口 | 品牌存在感要明确，但不要做营销式首页 |
| 主按钮 | 继续当前局 / 开始今日一题 | 根据是否有未完成游戏动态切换 |
| 次级入口 | 新开一局、难度设置、统计 | 保持少量、清晰、可快速理解 |
| 今日状态 | 今日是否完成、推荐难度、最近最好成绩 | 给用户一个轻量回访理由 |
| 文案反馈 | 跟随难度改变语气 | 入门更亲切，专家更克制 |

首页不建议放大段教程。新手引导应放在第一次进入棋盘时，用短提示逐步出现。

## 棋盘页设计

棋盘页采用固定结构：

| 区域 | 内容 |
|---|---|
| 顶部状态栏 | 难度、计时、错误数、暂停 |
| 中部棋盘 | 9x9 格，3x3 宫分隔明显 |
| 底部数字键盘 | 数字 1-9 |
| 工具栏 | 笔记、撤销、擦除、提示、检查 |

核心交互：

- 点击格子后，高亮当前格、同行、同列、同宫。
- 点击已有数字，高亮所有相同数字。
- 题目给定数字不可编辑，并使用更稳的字重或颜色。
- 用户输入数字略轻，和题目给定数字形成清晰区分。
- 错误数字根据当前档位决定是否立即标记。
- 候选数以小数字显示在格内九宫位置。
- 笔记模式、擦除、撤销、提示和检查应保持手指路径短、状态清楚。

我的建议是：棋盘页不要追求装饰感，应该优先保证数字辨识度、触控命中率和状态稳定。数独属于重复使用场景，耐看比惊艳更重要。

## 难度与辅助系统

| 档位 | 体验气质 | 排错 | 提示 | 候选数 |
|---|---|---|---|---|
| 入门 | 年轻、鼓励、轻游戏化 | 实时排错 | 可给答案并解释 | 可自动清理 |
| 进阶 | 日常练习、适度辅助 | 填入后提示 | 给技巧和下一步 | 默认自动清理 |
| 熟练 | 清爽、专注 | 手动检查 | 给方向和技巧 | 默认手动 |
| 专家 | 克制、专业 | 默认关闭 | 只给技巧/区域 | 手动 |

高级设置可允许用户覆盖默认值：

| 设置项 | 可选值 | 说明 |
|---|---|---|
| 提示深度 | 方向 / 格子 / 技巧 / 答案 | 控制提示从模糊到直接的程度 |
| 排错方式 | 关闭 / 冲突检查 / 答案检查 | 冲突检查只检查规则冲突，答案检查会判断是否符合解 |
| 候选数辅助 | 手动 / 自动清理 | 自动清理适合新手，手动适合老手 |
| 视觉风格 | 跟随难度 / 活力 / 清爽 | 默认跟随难度即可 |
| 计时显示 | 开启 / 关闭 | 给不想被计时压力影响的用户选择 |

高级设置不应在首屏堆太多。默认四档应该足够好用，高级项只给明确有需求的人。

## 提示系统

提示系统不是单纯“给答案”，而是按层级输出。

| 层级 | 作用 | 示例 |
|---|---|---|
| 方向提示 | 告诉用户看哪里 | 先看左上这一宫 |
| 格子提示 | 指出可突破的格子 | R3C2 可以确定一个数字 |
| 技巧提示 | 说明使用了什么技巧 | 这里是 Hidden Single |
| 答案提示 | 给出数字，并可一键填入 | R3C2 = 7 |

首版提示技巧建议：

| 技巧 | 中文说明 | 是否首版必做 |
|---|---|---|
| Naked Single | 唯一候选 | 是 |
| Hidden Single | 隐藏唯一 | 是 |
| Basic Elimination | 行列宫基础排除 | 是 |
| Box-Line Reduction | 区块排除 | 可作为增强项 |

不同档位的提示文案应不同：

| 档位 | 文案倾向 | 示例 |
|---|---|---|
| 入门 | 更像陪练，解释更多 | 先看左上这一宫，数字 7 只剩一个合适的位置 |
| 进阶 | 给方向和少量解释 | 左上宫可以通过排除法确定一个 7 |
| 熟练 | 简短，偏技巧 | Hidden Single，左上宫，数字 7 |
| 专家 | 专业、克制 | Hidden Single，R3C2，7 |

## 排错系统

排错分两类：

| 类型 | 说明 | 适用场景 |
|---|---|---|
| 冲突检查 | 检查同行、同列、同宫是否重复 | 不依赖完整答案，比较温和 |
| 答案检查 | 检查填入值是否等于解 | 帮助强，但会降低挑战感 |

我的建议：

- 入门档可以默认实时排错，但视觉反馈要柔和。
- 进阶档可以填入后提示，避免一直打断。
- 熟练档默认手动检查。
- 专家档默认关闭排错。

错误反馈不应该用过强的红色和警告语气。新手需要被扶一把，而不是被产品批评。

## 本地数据设计

本地保存四类数据：

| 数据 | 作用 |
|---|---|
| settings | 难度、辅助、视觉偏好 |
| currentGame | 当前棋盘、笔记、用时、历史操作 |
| puzzleBank | 内置题库 |
| stats | 完成数、连续天数、最好成绩、平均用时 |

题目结构示例：

```js
{
  id: "beginner-001",
  difficulty: "beginner",
  puzzle: "530070000600195000...",
  solution: "534678912672195348...",
  techniques: ["naked-single", "hidden-single"]
}
```

当前游戏结构示例：

```js
{
  puzzleId: "beginner-001",
  cells: [],
  notes: {},
  elapsedSeconds: 360,
  mistakes: 1,
  hintsUsed: 2,
  history: []
}
```

这里的重点不是结构最终一定长这样，而是首版要明确区分：题目原始数据、用户当前填写、候选数笔记、计时状态、操作历史和统计数据。

## 视觉策略

“九屿”的视觉不建议走传统“数独挑战”或“智力竞赛”风格，也不建议过度游戏化。更适合的方向是：清爽、轻盈、带一点陪伴感。

| 档位 | 视觉与动效建议 |
|---|---|
| 入门 / 进阶 | 更明亮的主色、更柔和的错误提示、完成一宫或一行时有轻动画、提示文案像陪练 |
| 熟练 / 专家 | 更干净的棋盘、弱化动效、工具栏紧凑、提示文案短而专业、完成页突出数据 |

需要注意：不同档位可以有气质差异，但不能变成四套完全不同的产品。棋盘结构、基础颜色体系、按钮位置和操作逻辑应保持稳定。

## MVP 范围

首版必须做：

| 模块 | 说明 |
|---|---|
| 首页 | 继续当前局、今日一题、新开一局、设置和统计入口 |
| 棋盘页 | 9x9 棋盘、输入、选格、高亮、候选数 |
| 设置页 | 四档难度和少量高级设置 |
| 完成页 | 用时、错误、提示次数、完成反馈 |
| 本地题库 | 按难度准备题目 |
| 本地存档 | 自动保存当前进度 |
| 本地统计 | 完成数、连续天数、最好成绩、平均用时 |
| 操作工具 | 笔记模式、撤销、擦除、暂停 |
| 辅助能力 | 排错、提示、检查 |

首版暂不做：

| 功能 | 暂不做原因 |
|---|---|
| 登录 | 增加流程和合规复杂度，首版不必要 |
| 云同步 | 需要服务端和账号体系，先本地闭环 |
| 好友排行 | 会把重点拉向社交增长 |
| 分享挑战 | 可后续作为传播功能 |
| 广告 | 过早商业化会影响体验判断 |
| 皮肤商城 | 非核心体验 |
| AI 提示 | 成本和稳定性不适合首版 |
| 复杂闯关地图 | 容易把产品做重 |

## 后续迭代路线

| 阶段 | 方向 | 说明 |
|---|---|---|
| 第二阶段 | 技巧训练专题 | 将提示系统沉淀为教学能力 |
| 第二阶段 | 每周挑战 | 给用户固定回访理由 |
| 第二阶段 | 题目收藏 | 方便用户复盘难题 |
| 第二阶段 | 解题回放 | 帮助提升专业感和复盘价值 |
| 第二阶段 | 更多高阶技巧提示 | 服务熟练和专家用户 |
| 第三阶段 | 云同步 | 在核心体验验证后再做 |
| 第三阶段 | 好友成绩 / 排行榜 | 作为增长和轻社交能力 |
| 第三阶段 | 活动题库 / 分享卡片 | 用于传播和运营 |

## 开发建议

建议首版开发按以下顺序推进：

1. 搭建微信小程序基础工程和页面路由。
2. 实现棋盘数据模型、渲染和数字输入。
3. 实现选格、高亮、候选数、撤销、擦除。
4. 接入本地题库和当前进度存档。
5. 实现基础排错和完成判断。
6. 实现提示系统的基础技巧。
7. 补齐首页、设置页、完成页、统计页。
8. 做手机端真机交互调优。

我的倾向是先把棋盘页打磨到可长期使用，再补外层页面。因为九屿真正的产品质感不在首页，而在用户连续输入几十次数字时是否顺手。

## 未决项 / 后续建议

| 项目 | 说明 |
|---|---|
| 小程序名称查重 | 上线前需要确认“九屿”能否注册 |
| 商标风险 | 若准备长期运营，应做基础商标检索 |
| 题库来源 | 需要确定是自建生成、引入公开题库，还是人工筛选 |
| 唯一解校验 | 题库必须保证唯一解，避免破坏信任 |
| 难度判定 | 需要建立可解释的难度分级规则 |
| 视觉稿 | 需要进一步确定色彩、字号、棋盘比例、按钮布局 |
| 小程序账号邮箱 | 注册小程序时需要使用未被微信公众平台/开放平台/企业号占用，且未绑定个人微信号的专用邮箱 |

## 给新线程的上下文说明

如果在新 Codex 线程中继续本项目，可以把本文件作为产品设计基线。当前最重要的执行方向是：

- 不要先做复杂平台功能。
- 先实现单人本地数独闭环。
- 棋盘页是第一优先级。
- 提示系统要逐层帮助用户思考。
- 难度系统要联动辅助强度和视觉气质。
- 首版完成标准是“稳定、顺手、愿意每天打开”，不是功能清单最长。
