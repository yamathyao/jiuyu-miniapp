# 九屿当前实施计划

> 当前主计划。用于统一小程序阶段实施计划、棋盘核心计划和小游戏迁移计划。  
> 以“先迁移为微信小游戏，再恢复并扩展数独闭环”为当前执行主线。

## 当前目标

把项目从微信小程序结构迁移为微信小游戏结构，并在小游戏模式下恢复数独主场景的最小可玩闭环。

当前的“完成”标准不是补齐原先所有页面，而是：

- 小游戏能启动
- 数独主场景能玩
- 纯逻辑测试仍然稳定

## 当前阶段划分

### 阶段 A：文档与方向收口

- 合并小程序阶段和小游戏阶段文档
- 明确当前主设计文档与主计划文档
- 把历史文档降为参考材料

### 阶段 B：小游戏入口切换

- 新建 `game.js`、`game.json`
- 将 `project.config.json` 切换为小游戏项目形态
- 让微信开发者工具不再报缺少 `game.json`

### 阶段 C：逻辑层迁移

- 把题库、数独工具函数、游戏引擎迁移到 `js/` 目录
- 保持 `tests/game-engine.test.js` 持续通过

### 阶段 D：主场景重建

- 使用 Canvas 2D 绘制棋盘
- 建立格子点击命中
- 建立数字输入区与底部工具区
- 接通笔记、撤销、擦除与高亮

### 阶段 E：旧结构清理

- 删除小程序专属入口文件
- 删除 `pages/*`、`components/*`
- 保留或迁移仍有价值的纯逻辑模块

### 阶段 F：后续功能恢复

小游戏主场景稳定之后，再按收益顺序恢复：

1. 本地存档
2. 提示与检查
3. 统计
4. 完成反馈
5. 更外围的日活与回访能力

## 当前实施边界

### 当前要做

- 小游戏入口与配置
- 数独纯逻辑迁移
- 单场景棋盘主循环
- 最小可玩闭环验证

### 当前不做

- 多页面导航恢复
- 首页面板
- 设置页
- 统计页
- 复杂动效
- 第三方引擎接入
- 云端能力

## 当前代码组织策略

迁移期间保持“双轨但单主线”：

- `js/` 目录是未来主线
- `miniprogram/` 在迁移完成前暂时保留作对照
- 一旦 `js/` 主场景跑通，再清理小程序专属目录

## 当前验证策略

### 自动化验证

- 持续运行 `node --test tests/game-engine.test.js`
- 每次迁移逻辑模块或接 UI 前后都要回归

### 手工验证

在微信开发者工具的小游戏模式中检查：

- 项目能按小游戏打开
- 不再报 `game.json` 缺失
- 能看到棋盘
- 能选格、输入、笔记、擦除、撤销
- 高亮与 `given` 只读行为正确

## 当前风险

- 工作区中已有与本次任务无关的配置变更，需要避免误提交
- 不能把“小程序页面结构”当成小游戏结构继续强保
- 迁移过程中如果失去纯逻辑测试护栏，UI 改造会很容易带来回归
